# Week 1 协作者立即执行清单设计

**日期：** 2026-07-17
**目标分支：** `codex/week1-collaboration`
**目标文件：** `docs/TEAMMATE_ONBOARDING.md`

## 1. 目标

将现有以 Task 2 初始接入为中心的 onboarding 完整替换为协作者当前可直接照做的 Week 1 任务清单。文档必须区分可立即开展的准备工作、依赖真人数据的标注工作，以及必须等待正式冻结后才能执行的 baseline、人工审计和阶段闸门工作。

## 2. 文件策略

保留 `docs/TEAMMATE_ONBOARDING.md` 的路径和 Git 历史，不新增第二份竞争入口，也不移动到 `docs/superpowers/`。旧内容整体替换，不保留已经过时的 Task 2 初始 onboarding 叙述。

## 3. 内容结构

新版文档依次包含：

1. 当前工程状态、数据阻塞和安全红线；
2. 开工前环境、分支和数据访问检查；
3. 固定数据准备与 manifest 核对；
4. 90 条查询类型/领域标记；
5. 40 条查询约束标注；
6. 固定 20 条双人独立标注、分歧复核和 kappa；
7. gold、ID 清单和 manifest 的真实冻结；
8. 冻结数据上的真实 Week 1 baseline；
9. 模糊去重人工抽样审计；
10. 去重/过滤 Recall 损失、失败率、成本和正式产物审核；
11. Week 1 阶段闸门进入条件；
12. 分阶段汇报模板。

每个工作包都明确输入、执行动作、输出、验收标准、阻塞条件和 Git/数据边界。

## 4. 关键约束

- 不读取、打印、搜索或复制 `.env` 内容。
- 真实查询、gold、人工标签、PaSa 原始文件和含受限文本的日志不得提交。
- 不得通过单独修改 manifest 状态伪造冻结。
- 正式冻结必须验证 revision、count、路径、精确字节 SHA-256、标签完整性、零答案策略、ID 唯一性及 gold/ID 顺序一致性。
- baseline 只有在真实冻结完成后才能运行和用于 Week 1 gate。
- 模糊去重准确率目标至少为 98%，过滤/去重 Recall 绝对损失不得超过 0.02。
- 协作者不自行修改评测算法、抽样种子、数据 revision、split ID 或 gold。
- 不修改或处理受保护的 Task 2 设计文档。

## 5. Git 交付

仅修改本设计说明和 `docs/TEAMMATE_ONBOARDING.md`。验证包括工作树范围、`git diff --check`、敏感信息模式扫描、占位符/矛盾检查和独立读者审查。完成后提交并推送 `codex/week1-collaboration`，不创建 PR、不合并、不强制推送。

## 6. 完成定义

协作者无需阅读旧对话即可从新版文档判断：现在能做什么、需要等待什么、每一步交付什么、哪些内容绝不能进入 Git，以及满足哪些证据后才能宣布 Week 1 gate 通过。
