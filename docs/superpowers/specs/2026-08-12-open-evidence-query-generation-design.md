# 开放检索证据画像与受约束论文表达生成设计

日期：2026-08-12

状态：待评审

验证框架：Scheme B Blind

## 1. 背景与决策

现有搜索词生成容易落入两个问题：一是先把 query 强制归入固定类别，再按类别套用模板；二是把自然语言机械改写成若干近义表达。前者依赖不稳定的 LLM 分类，新增 query 也可能超出预设类别；后者经常生成同质、过长或论文中不常出现的表达。

本设计不再使用原有八类标注，也不把后续分析提出的六类检索意图作为互斥分类器。统一流程改为：

1. 从 query 中建立开放的“检索证据画像”；
2. 在保留不可替换原词的前提下，生成论文常用表达；
3. 从候选表达中选择最多三条功能互补的搜索；
4. 使用已有 Scheme B Blind 框架，与先前的统一学术化方法做同条件比较。

“开放”表示画像由可并存、可缺省、可扩展的证据维度构成，而不是把 query 判成唯一类型。新增 query 即使出现当前未命名的线索，也可以保留为附加证据，而不要求先扩充封闭标签集合。

## 2. 目标与非目标

### 2.1 目标

- 保留 query 中方法名、模型名、数据集名、定理名、工具名、缩写、专有实体和精确短语等检索锚点。
- 将口语、任务描述或非专业表述映射为论文标题、摘要和关键词中更常见的表达。
- 生成一至三条搜索，每条承担不同的召回职责，避免只是同义改写。
- 对错误生成、零结果、重复覆盖和弱泛词污染形成可观测记录，供后续提示词收敛和 token 控制使用。
- 完全复用现有 Scheme B 的动作契约、实时检索、冻结标识符映射、报告和离线重放能力。

### 2.2 非目标

- 不恢复或替换成另一套互斥 query 分类体系。
- 不在本轮修改检索器、候选池、排序器、评测器、标识符解析或 Gold 数据。
- 不新增方法专用运行器、验证脚本、比较脚本或报告格式。
- 不让生成器看到 Gold 文献、Gold 标识符、Gold 标题或基于 Gold 形成的反馈。
- 不在首次快速验证后直接将方法设为默认生产方案。
- 不在本轮加入 citation search、title search 或后续检索反馈进化；先隔离验证搜索词生成本身。

## 3. 总体流程

```text
原始 query
  -> 内部开放证据画像
  -> 受约束的论文表达候选
  -> 风险过滤与互补选择
  -> 1~3 个既有 text_search 动作
  -> Scheme B Blind 检索、冻结、重放与评测
```

该流程只改变 recall generator 的提示词与实验 YAML。输出继续使用现有严格 `RecallActionBatch`，因此不需要扩展 Python 数据结构。

## 4. 开放检索证据画像

画像是生成器内部的临时分析，不作为新的输出字段持久化。它至少检查下列证据维度，但不要求每个 query 都具备所有维度：

| 证据维度 | 典型内容 | 生成作用 |
| --- | --- | --- |
| 受保护锚点 | 方法、模型、数据集、定理、缩写、专名、精确短语 | 原样保留，防止概念漂移 |
| 研究对象 | 系统、材料、人群、语言、网络、任务对象 | 确定论文讨论的主体 |
| 核心任务 | 检测、预测、生成、检索、证明、估计、优化 | 映射为论文常用任务术语 |
| 方法或机制 | 算法、架构、训练方式、实验机制 | 构造方法导向搜索 |
| 属性或结果 | 鲁棒性、复杂度、性能、偏差、可解释性、效果 | 构造性质或结论导向搜索 |
| 关系线索 | 比较、影响、因果、应用、组合、替代、限制 | 保留对象之间的语义关系 |
| 数据与场景 | 领域、数据模态、环境、时间、设备、语种 | 必要时用于消歧和约束 |
| 文献定位线索 | 作者、年份、题名片段、独特命名 | 构造精确定位表达 |
| 否定或边界 | 不含、不同于、无需、特定条件、例外 | 防止搜索方向反转 |
| 歧义与风险 | 缩写多义、口语多解、实体边界不清 | 控制是否扩展及扩展幅度 |

画像允许记录当前表中没有名称的新线索。它的核心产物不是一个类别，而是：

- 必须保留的词；
- 可以规范化的词；
- 可以谨慎推断的论文表达；
- 不足以推断、应保持原样或省略的部分；
- 最值得覆盖的一个或多个检索方向。

## 5. 受约束的论文表达生成

候选表达按来源分成三种，约束强度依次增加：

1. **显式表达**：直接来自 query，只做大小写、单复数或标准拼写规范化。
2. **规范化表达**：把用户用词映射为明确的论文常用术语，但不得增加新的研究对象、数据集、方法或结论。
3. **谨慎推断表达**：只有在语义对应关系清楚时才补充上位词、正式任务名或常见学术说法；一旦存在多种合理解释，就不把其中一种当作事实写入搜索词。

必须遵守以下生成约束：

- 受保护锚点至少出现在一条搜索中，除非它仅是无检索价值的格式噪声。
- 不把核心方法名替换成宽泛类别；可以在保留原词的同时增加一个正式上位词。
- 不凭空添加作者、年份、数据集、评测指标、模型家族、应用领域或论文结论。
- 不生成完整答案式伪摘要，不生成自然语言问句，不堆积形容词和低信息连接词。
- 每条搜索只保留完成该条职责所需的最小概念组合。
- 同一概念的拼写变体、单复数变体和近义词不得占用多条搜索配额。
- 若 query 已经是高辨识度论文表达，可以只输出一条搜索。

## 6. 最多三条互补搜索

生成器先形成候选，再按边际召回价值选择一至三条。三条不是固定模板，也不要求凑满：

1. **锚点搜索**：优先保留 query 中最有辨识度的原词及其必要关系。
2. **论文表达桥接搜索**：把非专业表达替换或补充为论文常用术语，同时保留足够的原始语义锚点。
3. **互补搜索**：仅在 query 明确存在另一个值得覆盖的证据组合时使用，例如“方法 + 任务”与“对象 + 属性”、精确定位与主题召回，或缩写与消歧全称。

每条动作仍使用现有 `text_search`。为便于沿用现有报告观察其职责，`strategy` 使用稳定前缀：

- `open-evidence:anchor`
- `open-evidence:scholarly-bridge`
- `open-evidence:complement`

若只有一条或两条有独立价值，则省略其余动作。生成器不得通过微小改写制造表面上的“互补”。

## 7. 错误规避与成本控制

输出前执行提示词内的自检：

- **概念漂移**：是否加入 query 未支持的新实体、新限定或新结论；若有则删除。
- **锚点丢失**：核心方法、专名或精确关系是否被泛化；若有则恢复。
- **过度约束**：是否把多个可选条件全部塞进一条搜索，导致零结果风险；若有则保留最必要组合。
- **弱泛词污染**：是否只剩通用词，如 performance、approach、study、analysis；若有则删除或与强锚点组合。
- **重复搜索**：不同动作的核心概念集合是否几乎相同；若相同则合并。
- **不自然论文表达**：是否仍是问句、命令句或长句；若有则压缩为名词短语和标准任务术语。
- **无依据扩展**：是否因常识联想而添加未出现且不唯一对应的术语；若有则删除。

成本限制为每个 query 最多三条检索动作，以及与现有框架一致的一次初始生成和至多一次结构修复。不存在有价值扩展时，少生成比凑满更优。

运行报告沿用现有字段总结：无效动作、修复发生率、零结果动作、每条动作候选产出、动作间重叠和独立贡献。失败表达不立即写成全局黑名单；只有跨多个 blind 样本重复出现的模式，才进入后续提示词规则，避免小样本过拟合。

## 8. 对照方法

快速验证包含两个只在提示词规则上不同的实验方法：

### 8.1 对照：统一学术化方法

对照提示词把先前已认可的做法固化为可重复版本：保留明确的核心方法词，把用户表述转换成论文常用词，并生成最多三条搜索。它不建立开放证据画像，也不要求三条搜索承担不同职责。

这不是对历史人工生成动作的逐字重放，而是对“统一学术化”规则的冻结实现。历史结果只作背景，不能与本次不同样本的结果直接合并。

### 8.2 实验：开放证据方法

实验提示词执行第 4 至第 7 节的完整流程，并使用稳定 `strategy` 标记三种动作职责。

两个方法都使用：

- 相同的 LLM 提供方、模型、温度和修复上限；
- 相同的 Scheme B 输入上下文；
- 相同的 `text_search` 能力与最多三条动作；
- 相同的 OpenAlex 检索、Top 50 截断、去重与标识符映射；
- 相同的 blind 样本、Gold 隔离和报告流程。

## 9. Scheme B Blind 快速验证协议

### 9.1 样本冻结

从冻结开发集顺序中选择前三个符合条件的 query：

- 未出现在此前的逐篇反推分析或 blind canary 中；
- 可通过现有冻结标识符映射得到至少一个可评测 Gold；
- 若遇到重复 query、解析冲突或框架预检失败，按原顺序选择下一个符合条件者。

样本清单必须在运行两个生成器之前由现有框架冻结；生成器和人工不得根据 Gold 文献内容调整样本。实际清单保存在既有忽略目录的运行输入/收据中，不把真实 query 或论文标识符写入公开设计文档。

### 9.2 运行顺序

1. 冻结对照与实验提示词、方法 YAML、模型参数和样本清单。
2. 对两个方法分别执行既有 Scheme B live capture。
3. 对 capture 执行零网络 replay，并确认候选与指标逐项一致。
4. 只有 replay 验证通过后才查看 Gold 指标并做比较。
5. 不根据首次结果即时修改提示词并重复报分；任何修订都必须形成新版本和新 canary。

### 9.3 指标

主指标沿用现有官方口径：

- Gold 命中数 / Gold 关联数；
- macro candidate recall；
- 每个 query 的 candidate recall；
- 零 Gold 命中 query 数。

诊断指标包括：

- 每个方法生成的动作数与生成 token；
- 结构校验失败和修复次数；
- 零结果动作数；
- 每条动作的候选数、独立新增候选数和独立 Gold 贡献；
- 动作两两重叠及重复饱和度；
- 被人工复核为概念漂移、弱泛词或无依据限定的动作数。

直接从原始 query 中可见的 arXiv 等标识符仅作为辅助诊断；官方判断继续使用冻结标识符映射，不能用辅助解析覆盖主指标。

### 9.4 判定规则

本轮只是小样本方法 canary，不作总体泛化结论。实验方法被视为“值得扩大验证”需同时满足：

- 不比对照少命中任何官方 Gold；
- 官方 Gold 总命中至少增加 1，或 macro candidate recall 严格提高；
- 没有新增明显的概念漂移动作；
- live capture 与零网络 replay 完全一致。

若只减少重复候选或 token，但官方召回不变，应记录为效率信号，不能宣称检索效果提升。若实验方法召回下降、出现新概念漂移，或 replay 不一致，则不进入扩大样本验证，先依据失败动作归因修改下一版本。

## 10. 实施范围

首次实施仅新增或修改以下实验资产：

- 一个冻结的“统一学术化”对照 prompt YAML；
- 一个“开放证据画像”实验 prompt YAML；
- 两个复用现有 Scheme B live recipe 的方法 YAML，均只允许 `text_search` 且最多三条动作；
- 针对提示词契约和 recipe 限制的现有测试文件用例。

若现有测试已能覆盖所需约束，不新增测试运行器。不得创建独立 Python 验证脚本、候选池实现、比较器或报告器。首次实验也不替换当前默认 prompt；只有 canary 通过且用户确认扩大验证后，才讨论默认接入。

## 11. 测试与验收

静态测试应确认：

- 两个方法都引用预期的冻结 prompt 版本；
- `max_actions` 为 3；
- 允许动作只有 `text_search`；
- Gold 字段在 blind 生成输入中不可见；
- 输出仍由严格 `RecallActionBatch` 校验，多余字段被拒绝；
- 实验 prompt 明确包含锚点保护、开放证据、受约束扩展、互补选择、去重和风险自检规则；
- 对照 prompt 不意外包含实验方法特有的画像与互补职责规则。

动态验收以第 9 节协议为准，并保存现有框架产生的输入清单、动作、检索收据、capture、replay 和比较报告。任何成功结论必须同时给出执行命令、退出状态和关键指标证据。

## 12. 风险与后续决策

- **画像不可直接审计**：当前严格动作契约不承载内部画像。本轮通过动作文本、`strategy` 职责和结果诊断间接审计。若后续确需完整画像，应另行设计版本化诊断 schema，不能偷加输出字段。
- **小样本波动**：三个 query 只能发现明显回归或正向信号。通过后仍需预注册更大、未分析样本。
- **LLM 非确定性**：固定模型、温度、prompt 版本和运行收据；对照和实验保持同等调用预算。
- **检索源变化**：必须 capture 后零网络 replay，以 replay 结果作为可复核证据。
- **规则膨胀**：失败模式只有跨样本重复时才上升为通用约束，避免把单一 Gold 的措辞反向编码进 prompt。

下一阶段是否扩大验证，取决于本次对照结果，而不是预先假定某套 query 类型能够覆盖全部输入。
