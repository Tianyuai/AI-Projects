# VivaAI GitHub 首页展示改版设计

日期：2026-08-29
状态：已实施并验证

## 目标与受众

首页采用“比赛评委优先、开源开发者兼顾”的双层信息结构：评委应在 30 秒内理解项目解决的问题、端到端能力和可信证据；开发者应在 90 秒内找到零网络验证命令、完整文档与 Live 运行入口。

## 首屏设计

首屏按以下顺序组织：

1. 居中的 VivaAI 项目名和一句话价值主张；
2. 仅使用可核验的静态能力徽章，不展示不存在的 CI、License、Release 或性能徽章；
3. “快速验证、评委手册、系统架构、演示手册”四个高价值入口；
4. 一张由当前生产 Replay UI 实际生成、完成隐私清理的截图；
5. 三项核心价值：复杂意图理解、多源可追溯召回、统一排序与零网络复现。

## 正文信息架构

1. **为什么是 VivaAI**：从复杂科研任务、约束组合和可审计交付切入。
2. **端到端流程**：使用 GitHub 可渲染的 Mermaid 图，展示 Query、LLM QuerySpec、监督词汇桥、OpenAlex/S2、身份治理、候选池、F5/F4/B0、UI/API/CLI/JSONL、回执与 Replay。
3. **90 秒零网络验证**：保留并压缩现有 safe replay 命令，明确无需 API 密钥。
4. **能力矩阵**：查询理解、召回、身份统一、固定排序规则、成本、回执和多入口交付。
5. **生产证据**：仅陈述已有封存制品能够支持的规模与工程门禁，不包装为公开或隐藏测试成绩。
6. **Live 与 Replay**：用短表格解释用途、费用和复现差异。
7. **文档导航**：面向评委、开发者和维护者分别提供最短入口。
8. **安全与边界**：说明仓库不包含密钥、私有训练数据、Gold 标签和最终/隐藏测试集。

## 视觉资产

- 新增 `docs/assets/vivaai-ui-replay.png`，必须来自当前生产锁下的本地 Replay UI，不得人工拼接结果或使用历史废弃界面。
- 不创建装饰性 AI 插画，不使用无法核验的成绩图和外部品牌 Logo 墙。
- 使用简洁的蓝色视觉语义，与现有 UI 和项目文档保持一致。

## 内容真实性规则

- 对外使用完整方法名称；F5/F4/B0 只在固定回退映射说明中出现。
- OpenAlex 是主召回；Semantic Scholar 仅按实际状态描述为受控补充。
- PASA 只描述为生产身份别名与去重能力，不描述为线上候选来源。
- 7,502、18,314、538 等数字必须能在当前制品或冻结证据中复核，并明确各自含义。
- 不声称单条展示结果是 Gold、官方答案或最终比赛成绩。

## 实施边界

- 只修改根目录 `README.md` 并新增一张真实 UI 截图；不改生产代码、模型、生产锁、训练数据或项目文档。
- 保留现有 PowerShell 快速验证路径，避免为了视觉效果增加新的运行依赖。
- 不触碰工作区中已有的排序实验和其他未提交修改。

## 验证标准

1. README 内部链接与本地文件全部存在；外部链接可访问。
2. safe replay 命令与评委运行包路径保持一致。
3. Mermaid 语法、Markdown 标题、表格和折叠区块能够被 GitHub 正常解析。
4. 截图不含密钥、用户名、绝对路径、Gold 或私有测试信息。
5. 新读者可以从首页回答：系统解决什么问题、如何运行、LLM 与两个检索源各做什么、排序如何回退、为什么结果可复现。
